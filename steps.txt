4. PDF Processing

Technology: PyMuPDF

Flow:

PDF
 ↓
Extract text page-by-page
 ↓
Keep page numbers

Purpose:

Convert PDF into usable text while preserving source pages.

5. Chunking

Technology: Python

Flow:

Large text
 ↓
Smaller chunks
 ↓
Overlap between chunks

Purpose:

Make documents easier to search and provide focused context to the LLM.

6. Embeddings

Technology: Sentence Transformers

Model:

all-MiniLM-L6-v2

Flow:

Text
 ↓
Embedding Model
 ↓
384-dimensional vector

Purpose:

Convert text into numerical representations for semantic search.

7. Similarity Search

Technology: scikit-learn + ChromaDB

Concept:

Question Vector
       ↓
Compare with document vectors
       ↓
Find most similar chunks

Important:

Cosine similarity → higher = more similar

Cosine distance → lower = more similar
8. Vector Database

Technology: ChromaDB

Stores:

Chunk
Embedding
Document ID
Filename
Page number

Purpose:

Store and retrieve document information based on semantic similarity.

9. Document ID

Each uploaded PDF gets a unique ID.

Purpose:

PDF A → document_id A
PDF B → document_id B

When asking about PDF A:

Search only document_id A

This prevents mixing documents.

10. RAG Pipeline

The most important part:

Question
 ↓
Question Embedding
 ↓
ChromaDB Similarity Search
 ↓
Relevant Chunks
 ↓
Context
 ↓
LLM
 ↓
Answer + Source Pages

RAG = Retrieval + Augmentation + Generation
